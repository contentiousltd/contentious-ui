Coachmarks – deferred

Same message as the tooltip. Better as its own strand.

Cut from this component. The coachmark and the tooltip said the same sentence, and of the two the tooltip is the better deal: it’s there every time someone hesitates, not once on a day they may not be paying attention, and it needs no dismissal state, no "seen" flag per user, and no decision about when to re-show it.

The switcher shouldn’t need a tip to be usable. If it does, that’s a signal the menu itself is wrong – so the tooltip is a convenience, and a coachmark on top of it would be an admission the design didn’t work.

Worth doing properly, separately: a guided tour, on demand, from the account menu – so it’s repeatable, skippable, and never fires at someone mid-task. That’s a different shape of work to a single tip: it needs a step sequence, progress, an exit at any point, and copy that survives being read out of order.

What it would cover: the four tiers (estate → inventory → catalogue → results), what a project scopes, where credits are spent, and how a scheduled re-assessment differs from a manual run. Those are the concepts people actually get stuck on – all bigger than "this dropdown switches projects".

Rules

Bar shows the name only
No mono label, no client prefix, no path. The bar’s job is to state where you are; everything explanatory lives in the menu or the tooltip.
Menu header does the labelling
Project · Oxfam 2 on one line above a hairline. Present in every variant including the single-project case, so the word in the bar is always defined one click away.
Group only when it earns itself
A client header appears only above clients with two or more projects. One-project clients render as plain rows, so no name is ever printed twice.
Current project isn’t a destination
In a flat list it’s simply absent – the header already names it, so the list is only things you can go to. Inside a client group it stays visible but greyed and unclickable, so the group’s count always matches its rows.
Progressive disclosure
Search past six projects. Grouping only once a multi-project client exists. "All clients & projects" only for accounts that have clients. Nothing appears before it’s needed.
Domains, not client names
The secondary line is always the domain – it separates "Oxfam" from "Oxfam 2" where a client name can’t, and it’s the thing actually being audited.
