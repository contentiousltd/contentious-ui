Project is context, not a list

One block naming where you are, opening a switch sub-panel. Rendering the projects inline spends the top four rows on a once-a-session question and makes them look like the sections.

Mark the page, not the project

The desktop’s fire marker on the current section. Never a “You’re here” chip on the project – the wordmark, page title and context block already say it.

Funnel order, fixed

Estate → Inventory → Watchlist → Results, as in the bar. Never promote the current page to the top: a menu that reorders itself can’t be learned.

Account at the bottom, on chrome

Labelled, smaller, own surface, doesn’t scroll with the work – and in the thumb zone, which is the right trade for the group tapped least.

Site pages: one row, not nine

Framework, Pricing, the Learn explainers and the legal pages open a sub-panel from a single quiet row — in its own band below the rule, so it isn’t read as an account item. Nine footer links as rows would rebuild the flat list this pattern exists to fix.

A layer, not a page

330px over a scrim, in from the burger’s side on --motion-reveal, out on --motion-exit. Full-bleed is what makes a menu read as a destination.
